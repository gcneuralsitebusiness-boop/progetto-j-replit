╔══════════════════════════════════════════════════════════╗
║ 1. VINCOLI DI PERFORMANCE — leggi prima di tutto         ║
╚══════════════════════════════════════════════════════════╝

Questa pagina NON deve rallentare il sito. Regole non negoziabili:

- NESSUNA libreria di mappe. Vietati: Leaflet, Mapbox, react-simple-maps,
  d3-geo, topojson-client, Google Maps. Zero dipendenze nuove nel bundle.
- L'SVG del mondo va incluso come file statico in /public/mappa-mondo.svg
  e caricato con fetch + dangerouslySetInnerHTML, NON importato come
  componente React. Un world map inline in JSX aggiunge 200-600 KB al
  bundle JS e blocca il primo render.
- Usa una mappa a BASSA risoluzione (semplificata, ~50-120 KB). Una mappa
  ad alta densità di vertici manda in crisi il rendering su mobile.
  Se il file supera 150 KB, semplificala prima di usarla.
- Code splitting: la pagina va caricata con React.lazy + Suspense, così
  la mappa non pesa sulle altre rotte.
- Colorazione paesi: applica le classi UNA VOLTA SOLA dopo il caricamento
  dell'SVG, dentro un useEffect con dependency array vuoto. NON ricolorare
  a ogni render, NON usare state per i colori dei paesi.
- Vietate transizioni CSS su fill dei path. Con centinaia di path la
  transizione fa collassare il framerate su mobile.
- I punti delle tappe sono <circle> React sovrapposti all'SVG in un layer
  separato, posizionati in percentuale. NON toccare l'SVG per aggiungerli.
- Fallback: se il fetch dell'SVG fallisce, mostra comunque le quattro
  schede tappa e i contatori. La pagina non deve mai risultare vuota.

╔══════════════════════════════════════════════════════════╗
║ 4. MAPPA — regole di colorazione                         ║
╚══════════════════════════════════════════════════════════╝

Prima di scrivere il CSS, VERIFICA che i path dell'SVG scelto abbiano
id o attributo data corrispondente al codice ISO-3166 alpha-3 (es. "ITA").
Se usano nomi o codici a due lettere, adatta la mappatura. Se non lo
verifichi, niente si colorerà e non sarà evidente il motivo.

.paese              fill #0A0A0A, stroke #2A2A2A, stroke-width .8
.paese--visitato    fill #B81D1D, stroke #0A0A0A, stroke-width .8
.paese--pianificato fill #8B6914, stroke #0A0A0A, stroke-width .8

Oceano/sfondo mappa: #0A0A0A, nessun bordo, nessuna griglia.

CRITICO — Dagestan e Rio de Janeiro NON sono paesi.
Il Dagestan è una repubblica della Federazione Russa, Rio è una città.
Colorare Russia e Brasile interi direbbe una cosa falsa.
  - coloraPaese: true  → il paese viene riempito di bronzo (THA, NLD)
  - coloraPaese: false → il paese resta #0A0A0A, compare SOLO il punto
Russia e Brasile restano quindi non colorate.

╔══════════════════════════════════════════════════════════╗
║ 5. MAPPA — punti tappa                                   ║
╚══════════════════════════════════════════════════════════╝

Layer assoluto sopra l'SVG, position: absolute, inset: 0, pointer-events
solo sui punti.

Ogni tappa:
  - quadrato 9x9px #8B6914 (NON un cerchio: il design system è brutalista,
    zero raggi, quindi il marcatore è un quadrato)
  - anello esterno: quadrato 19x19px, solo bordo 1px #8B6914 a opacità .45
  - linea sottile 1px #8B6914 opacità .6 che collega il marcatore
    all'etichetta
  - etichetta: JetBrains Mono 11px letterSpacing .14em maiuscolo #8B6914,
    formato "01 · MUAY THAI"

Posizionamento: converti lat/lng in percentuale con proiezione equirettangolare
  x% = (lng + 180) / 360 * 100
  y% = (90 - lat) / 180 * 100
Se l'SVG usa Mercator, applica invece:
  y = (1 - Math.log(Math.tan(latRad) + 1/Math.cos(latRad)) / Math.PI) / 2 * 100
Verifica visivamente che i quattro punti cadano nel posto giusto e correggi
se serve — questa è la parte che sbaglia più spesso.
