B1 — TIMELINE NUMBERS DO NOT ADD UP
═══════════════════════════════════════════

FILE: artifacts/progetto-j/src/components/Timeline180.tsx

The stats line reads "71 registrati · giorno 76 di 180 ·
104 rimanenti". 71 + 104 = 175, not 180: "registrati"
counts DB rows while "rimanenti" subtracts currentDay.

Replace with a single coherent basis:
  const logged = completedDays.size;
  const skipped = currentDay - logged;
  const remaining = total - currentDay;

Render:

  {skipped > 0 ? ` · ${skipped} saltati` : ""}
  · {remaining} rimanenti

B3 — BACKFILL MISSING DAYS
═══════════════════════════════════════════

FILE: artifacts/api-server/src/lib/ensureToday.ts

ensureTodayEntry() only creates today. If the deployment
sleeps for several days, those days are never created —
which already happened (31 July and 1 August were missed).

Extend it to fill gaps:
1. Find MAX(data) among existing entries
2. If the gap between that date and today exceeds one
   day, create an entry for EVERY missing date in
   between, incrementing numero sequentially
3. Cap the backfill at 30 days
4. Log each created day: "Created day N for YYYY-MM-DD"

Keep the per-date duplicate check and
onConflictDoNothing on every insert.

B4 — NOTIFICATION ON CONTACT AND SUBSCRIBE
═══════════════════════════════════════════

Submissions to /api/contact and /api/subscribe are
stored but nobody is notified. A client enquiry can sit
unseen for days.

1. pnpm --filter @workspace/api-server add resend

2. Two new env vars, both supplied by the user — never
   hardcode an address:
     RESEND_API_KEY
     NOTIFICATION_EMAIL

3. CREATE artifacts/api-server/src/lib/notify.ts
   export async function notify(subject: string,
                                body: string)
   Sends plain text to NOTIFICATION_EMAIL via Resend.
   If RESEND_API_KEY is absent, log a warning and return
   silently. Never throw.

4. Call notify() after a successful insert in
   routes/contact.ts and routes/subscribe.ts, wrapped in
   try/catch. The HTTP response must return 201 even if
   the notification fails.
