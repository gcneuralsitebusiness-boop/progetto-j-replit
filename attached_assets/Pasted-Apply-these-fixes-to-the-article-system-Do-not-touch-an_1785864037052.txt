FIX 1 — SILENT FAILURE ON SUBMIT
═══════════════════════════════════════════

FILE: artifacts/progetto-j/src/components/admin/ArticoliTab.tsx

The submit button appears "dead" because create.mutate
and update.mutate have no onError handler. If the admin
session expired or the request fails, nothing happens —
no message, no feedback.

Add error state and display it:

const [submitError, setSubmitError] = useState<string | null>(null);

In handleSubmit, before calling mutate, clear submitError.
Add onError to both create.mutate and update.mutate:

  onError: (err) => {
    setSubmitError(
      err instanceof Error && err.message.includes("401")
        ? "Sessione scaduta. Ricarica la pagina e rientra."
        : "Salvataggio fallito. Riprova."
    );
  }

Render submitError above the submit button, if present:

  {submitError && (
    <p className="text-[13px] font-sans text-primary
       border border-primary/40 bg-primary/10 px-4 py-3">
      {submitError}
    </p>
  )}

Also add a visible required-field check before submit:
if slug or titolo is empty after trim, set submitError
to "Slug e titolo sono obbligatori." and return early —
do not rely only on the native HTML `required` attribute,
which can fail silently inside some mobile browsers when
the field is scrolled out of view.

FIX 3 — SLUG AUTO-GENERATION
═══════════════════════════════════════════

Same file. Typing a slug by hand is friction and error
prone (spaces, accents, capitals all break routing).

When titolo changes AND the user has not manually edited
slug yet (track with a `slugTouched` boolean, set to true
only on direct input in the slug field), auto-generate:

  const autoSlug = titolo
    .toLowerCase()
    .normalize("NFD").replace(/[\u0300-\u036f]/g, "")
    .replace(/[^a-z0-9\s-]/g, "")
    .trim()
    .replace(/\s+/g, "-");

Keep the slug field editable manually — once the user
types in it directly, stop auto-updating it.

FIX 5 — CONTENT EDITOR: LIVE WORD COUNT
═══════════════════════════════════════════

Same file. Long articles are hard to gauge in a plain
textarea.

Below the contenuto textarea, add a small line:
  Inter 11px, text-muted-foreground:
  "{wordCount} parole · lettura ~{readMinutes} min"

  const wordCount = form.contenuto.trim()
    ? form.contenuto.trim().split(/\s+/).length : 0;
  const readMinutes = Math.max(1, Math.round(wordCount / 200));

Also increase the textarea to rows={16} and add
font-family: var(--app-font-mono) for the editing view
only (monospace makes long-form editing easier to scan;
the published page keeps using Inter).
