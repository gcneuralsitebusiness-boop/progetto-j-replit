═══════════════════════════════════════════

GET /api/admin/backup — admin session required.
Returns a single JSON file (Content-Disposition:
attachment; filename="progetto-j-backup-YYYY-MM-DD.json")
containing every row from: giorni, contenuti, pagine,
social, sponsor, articoli, coaching, contatti, iscritti.

Wrap each table in a top-level key. Include an
exportedAt timestamp and a schemaVersion field.

In the admin UI, add a "BACKUP" button in the dashboard
header that hits this endpoint and triggers the download.

This is the top priority: the 80+ days of diary data
currently exist only inside Replit.

3 — DIARY FORM AUTOSAVE (local only)
═══════════════════════════════════════════

FILE: the diary editing component in admin (DiarioTab
or equivalent)

While editing an entry, debounce-save the form state to
a local draft keyed by day number. Use an in-memory ref
plus a state mirror — do NOT use localStorage (it is
blocked in some embedded contexts); instead persist the
draft to a new endpoint:

POST /api/admin/drafts { numero, formJson } (admin only,
upsert into a new "bozze" table: numero PK, dati jsonb,
updated_at). GET /api/admin/drafts/:numero returns it.

On opening an entry, if a draft newer than the saved
entry exists, show a bar: "Bozza non salvata del {time}.
[Ripristina] [Ignora]".

On successful save of the real entry, delete the draft.

4 — ENTRY VALIDATION
═══════════════════════════════════════════

FILE: the diary form component AND
artifacts/api-server/src/routes/entries.ts

Add range validation, both client and server side:
  peso: 30–200 (kg)
  battito: 30–220 (bpm)
  sonno: 0–24 (h)
  kcal: 0–15000
  km: 0–100
  flessioni/addominali/round: 0–2000
  entrate/uscite: 0–100000

Client: show an inline red message under the field and
block submit. Server: return 400 with a clear message
if any value is out of range. Null is always allowed.
